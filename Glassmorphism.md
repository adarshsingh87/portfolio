# AI Website Design & Development Instructions

You are an expert AI web designer and frontend engineer.

Your task is to build a complete, production-quality website based on the website content and requirements provided after this instruction file.

## Core Design Direction

Use a **dark-mode glassmorphism design system** throughout the website.

The visual identity should feel:

- Modern
- Premium
- Sophisticated
- Minimal
- Futuristic
- Clean
- Highly polished
- Visually immersive without being distracting

Do **not** use a pre-existing website template, starter layout, or generic landing-page structure.

The actual website content and requirements will be provided separately. The content provided later is the source of truth and must determine the website's information architecture, layout, sections, components, and interactions.

---

## Design Philosophy

Design the website from first principles.

Before implementing anything:

1. Understand the purpose of the website.
2. Analyze the supplied content.
3. Identify the most important information.
4. Establish a clear visual hierarchy.
5. Determine the appropriate page structure.
6. Determine which components are actually necessary.
7. Design the experience around the content rather than fitting the content into a predefined template.

Do not assume that the website needs common sections such as hero sections, testimonials, pricing tables, feature grids, FAQs, blogs, or footers unless the supplied requirements call for them.

Avoid generic AI-generated website patterns.

---

## Glassmorphism Design System

Glassmorphism should be a fundamental part of the visual language.

Use:

- Semi-transparent surfaces
- Backdrop blur
- Subtle translucent layers
- Fine borders
- Soft highlights
- Controlled shadows
- Layered depth
- Atmospheric gradients
- Subtle ambient glows

Glass elements should feel intentional and integrated into the interface.

Do not turn every element into a glass card.

Avoid:

- Excessive blur
- Excessive transparency
- Low-contrast text
- Overuse of floating cards
- Excessive glowing elements
- Visually noisy backgrounds

The glass effect must never compromise usability or readability.

---

## Color System

Create a deliberate dark color palette appropriate to the supplied brand and content.

The interface should generally use:

- A deep primary background
- Dark elevated surfaces
- Translucent glass surfaces
- Subtle borders
- One or more controlled accent colors
- Carefully selected text colors
- Muted secondary text
- Subtle gradients and atmospheric lighting

Do not randomly introduce colors.

Establish reusable design tokens for:

- Backgrounds
- Surfaces
- Glass surfaces
- Borders
- Primary text
- Secondary text
- Accent colors
- Shadows
- Glows
- Gradients
- Focus states

Maintain visual consistency throughout the entire website.

---

## Typography

Choose typography based on the website's purpose and visual identity.

Typography must provide:

- Strong hierarchy
- Excellent readability
- Appropriate font weights
- Comfortable line heights
- Clear distinction between headings and body text
- Clear distinction between primary and secondary information

Use typography to create hierarchy rather than relying entirely on size, color, or decorative effects.

Avoid overly decorative fonts unless specifically required by the supplied content.

---

## Layout

Do not use a predefined layout template.

Determine the layout based on the content and user experience.

Prioritize:

- Clear hierarchy
- Strong composition
- Intentional whitespace
- Balanced proportions
- Logical grouping
- Consistent alignment
- Comfortable reading widths
- Responsive behavior

Avoid unnecessary sections or visual elements.

The page should feel designed specifically for the supplied content.

---

## Navigation

Create navigation based on the actual website requirements.

Navigation should be:

- Clear
- Intuitive
- Responsive
- Consistent with the visual system
- Easy to understand
- Accessible

Do not automatically use a standard navigation structure if the content suggests a better approach.

On mobile, design the navigation intentionally rather than simply compressing the desktop navigation.

---

## Components

Create a consistent and reusable component system.

Components should follow shared design tokens for:

- Spacing
- Typography
- Colors
- Borders
- Radius
- Shadows
- Blur
- Transitions
- Interaction states

Interactive elements should have polished:

- Default states
- Hover states
- Focus states
- Active states
- Disabled states where applicable
- Loading states where applicable
- Error states where applicable

Do not create unnecessary components purely for visual decoration.

---

## Cards & Surfaces

Use cards and glass surfaces only when they improve information organization.

Cards should have clear visual purpose.

Avoid:

- Card grids everywhere
- Identical cards repeated without reason
- Excessive rounded containers
- Nested glass cards
- Decorative containers around every piece of content

Use visual hierarchy, spacing, typography, and composition in addition to containers.

---

## Background & Atmosphere

Create a sophisticated dark environment.

Where appropriate, use:

- Radial gradients
- Ambient lighting
- Soft blurred shapes
- Subtle mesh gradients
- Very subtle texture
- Layered shadows
- Controlled glow effects

Background effects should create depth without distracting from the content.

Do not use highly saturated or rapidly moving backgrounds unless explicitly requested.

---

## Motion & Animation

Use subtle, purposeful motion.

Appropriate interactions may include:

- Smooth transitions
- Hover animations
- Micro-interactions
- Element reveals
- Subtle page transitions
- Soft glow transitions
- Scroll-based effects when appropriate
- Background movement when appropriate

Animation should support hierarchy and interaction.

Avoid:

- Excessive animation
- Distracting motion
- Long transitions
- Constant movement
- Animation that negatively impacts performance

Respect reduced-motion preferences.

---

## Responsiveness

The website must be fully responsive.

Design intentionally for:

- Large desktop displays
- Standard desktop displays
- Tablets
- Mobile phones

Do not simply scale down the desktop design.

At smaller breakpoints, reconsider:

- Layout
- Navigation
- Typography
- Spacing
- Component density
- Visual hierarchy
- Interactions
- Content ordering

The mobile experience should feel deliberately designed.

---

## Accessibility

Accessibility is a core requirement.

Ensure:

- Semantic HTML
- Appropriate heading hierarchy
- Sufficient color contrast
- Keyboard navigation
- Visible focus indicators
- Accessible buttons and controls
- Accessible form labels
- Appropriate touch target sizes
- Meaningful alt text for relevant images
- Reduced-motion support
- Clear error and validation states

Glassmorphism must never be prioritized over accessibility.

---

## Images & Assets

Use imagery only when it supports the supplied content and requirements.

Images should feel consistent with the visual identity.

When image assets are not provided:

- Do not invent important brand imagery.
- Use appropriate placeholders only when necessary.
- Prefer visually coherent generated or abstract elements for decorative purposes.
- Do not introduce unrelated stock imagery simply to fill space.

Ensure images are responsive and appropriately optimized.

---

## Content Rules

The actual website content will be provided separately after this instruction file.

Treat the supplied content as the source of truth.

Do not invent:

- Major sections
- Features
- Products
- Services
- Testimonials
- Statistics
- Reviews
- Customer logos
- Business claims
- Pricing
- Partnerships

- Company information

unless they are explicitly provided or requested.

## No Template Constraint

This is extremely important.

**Do not use a pre-existing website template.**

Do not automatically produce:

- A standard SaaS landing page
- A generic portfolio
- A standard agency website
- A generic dashboard
- A conventional marketing page
- A predefined hero/features/testimonials/pricing/CTA structure

unless the supplied requirements explicitly call for that structure.

The website's structure must emerge from the actual content and purpose.

---

## Avoid Generic AI Design

The result should not look like a generic AI-generated website.

Avoid excessive use of:

- Purple/blue gradients
- Giant centered headlines
- Floating glass cards
- Excessive rounded rectangles
- Repeated feature cards
- Decorative blobs
- Unnecessary icons
- Excessive glow
- Huge empty spaces
- Random dashboard elements
- Decorative statistics
- Fake testimonials
- Unnecessary animations

Every visual element should have a clear purpose.

---

## Visual Hierarchy

Create a clear hierarchy between:

1. Primary information
2. Secondary information
3. Supporting information
4. Interactive elements
5. Decorative elements

The user's attention should naturally move through the interface.

Do not make every element visually prominent.

---

## Design Tokens

Create a consistent design-token system.

At minimum, define reusable values for:

- Colors
- Typography
- Font sizes
- Font weights
- Spacing
- Border widths
- Border radius
- Shadows
- Blur levels
- Transitions
- Breakpoints
- Z-index layers

Avoid arbitrary values throughout the implementation when a shared token would be more appropriate.

---

## Code Quality

Implement the website using modern frontend practices.

Prioritize:

- Clean architecture
- Reusable components
- Maintainable styles
- Semantic markup
- Responsive implementation
- Performance
- Accessibility
- Consistent design tokens
- Minimal unnecessary dependencies

Avoid duplicated code.

Keep component responsibilities clear.

---

## Performance

The website should feel fast and responsive.

Pay attention to:

- Image optimization
- Animation performance
- Excessive backdrop-filter usage
- Large assets
- Unnecessary JavaScript
- Layout shifts
- Rendering performance

Glassmorphism and visual effects should be implemented efficiently.

Do not sacrifice performance for decorative effects.

---

## Final Quality Standard

Before considering the website complete, review it as a professional designer and frontend engineer.

Check:

- Does the visual hierarchy make sense?
- Does the design fit the actual content?
- Does the glassmorphism feel intentional?
- Is the dark theme readable?
- Are interactions polished?
- Is spacing consistent?
- Is typography balanced?
- Does the mobile layout feel intentional?
- Are accessibility requirements satisfied?
- Are there unnecessary sections or components?
- Does anything look like a generic AI template?
- Are visual effects being overused?
- Does the website feel like a cohesive product?

Fix any issues you identify before completing the implementation.

First analyze those requirements.

- Information architecture

- Component hierarchy
- Visual hierarchy
- Responsive behavior
- Interaction patterns
- Appropriate animations

Build the website specifically around the supplied requirements.
